# Автоматическое развёртывание RU → exit split VPN

Репозиторий содержит Ansible playbook для следующей схемы:

- клиент подключается к RU по VLESS + XHTTP + REALITY на `443/tcp`;
- российские домены и IP выходят напрямую с RU;
- YouTube, Telegram и остальной зарубежный трафик идут RU → exit по отдельному
  VLESS + XHTTP + REALITY-транзиту;
- 3x-ui работает только на `127.0.0.1` и открывается через SSH-туннель;
- ключи, UUID и пароли создаются отдельно для каждого развёртывания и хранятся
  только на серверах с правами `0600`.

После настройки playbook запускает на exit-сервере временный Xray-клиент и проверяет
полный путь через RU, прямой доступ к российскому сервису, YouTube, Telegram и
фактический внешний exit IP. Временный клиентский конфиг затем удаляется.

`exit` — это роль второго сервера. Он может находиться, например,
в Германии, Нидерландах, Финляндии или Казахстане.

## Структура

```text
site.yml                    # короткий оркестратор четырёх play
inventory.example.yml       # безопасный пример inventory
group_vars/all.yml          # общие несекретные параметры
roles/
  preflight/                # проверка inventory и параметров
  exit_node/                # standalone Xray на зарубежном exit
  ru_gateway/               # 3x-ui, клиентский inbound и split routing
  e2e_verify/               # проверка полного пути временным клиентом
```

Скрипты и Jinja-шаблоны находятся внутри тех ролей, которые их используют.
Корневой `site.yml` содержит только порядок запуска, параметры связи между
хостами и подключение ролей.

## Требования

- локально: Ansible Core 2.16+;
- два свежих x86_64 VPS на Debian 12 или Ubuntu 24.04;
- SSH-доступ к обоим VPS и право `sudo` (для `root` ничего дополнительно не
  требуется);
- входящий настроенный SSH-порт и `443/tcp` на обоих VPS;
- рабочий маршрут RU → exit на `443/tcp`.

Playbook рассчитан на чистые серверы, повторный запуск после предыдущего
развёртывания этим playbook и принятие совместимой ручной установки, созданной
ранней версией проекта. Он не импортирует произвольную чужую панель 3x-ui.

## Быстрый запуск

```bash
cp inventory.example.yml inventory.yml
```

Укажите IP и SSH-пользователей в `inventory.yml`:

```yaml
all:
  children:
    ru:
      hosts:
        ru_gateway:
          ansible_host: 203.0.113.10
          ansible_user: root
    exit:
      hosts:
        exit_node:
          ansible_host: 198.51.100.20
          ansible_user: root
```

При необходимости для каждого хоста можно добавить `ansible_port` и
`ansible_ssh_private_key_file`. Временный firewall-guard установщика автоматически
разрешит порт из `ansible_port`.

Если адрес для SSH отличается от публичного адреса VPN, добавьте хосту
`vpn_public_ip`. В обычной конфигурации этот параметр не нужен: используется
`ansible_host`.

Проверьте доступ:

```bash
ansible all -i inventory.yml -m ping
```

Перед первым запуском подключитесь к каждому IP обычным `ssh` и проверьте его
host key. Для парольного SSH добавьте `--ask-pass` к команде `deploy.sh`.

Разверните схему:

```bash
./deploy.sh
```

Для пользователя с `sudo`, требующим пароль:

```bash
./deploy.sh inventory.yml --ask-become-pass
```

В конце Ansible напечатает:

- команду SSH-туннеля;
- локальный URL панели;
- логин и пароль 3x-ui;
- готовую клиентскую `vless://` ссылку.

## Настройки

Несекретные параметры находятся в `group_vars/all.yml`. Там можно изменить:

- закреплённые версии Xray и 3x-ui;
- REALITY targets для RU и exit-сервера;
- имя первого клиента;
- списки сервисов, принудительно направляемых через exit;
- дополнительные домены российских сервисов для прямого выхода через RU;
- блокировку QUIC/HTTP3 через `block_quic`;
- локальный порт SSH-туннеля.

`additional_ru_direct_domains` содержит только базовые имена: указанный домен и
его поддомены выходят через RU. Добавляйте туда только доверенные зависимости
российских сервисов, поскольку такой трафик намеренно не использует exit-сервер.

При `block_quic: true` UDP на порту `443` блокируется, и обычные браузеры
переходят на TCP/TLS. Это делает каскад предсказуемее, но отключает HTTP/3 и
может ломать приложения, работающие только по QUIC. Для сохранения QUIC задайте
`block_quic: false`.

Перед использованием нового REALITY target проверьте на соответствующем сервере:

```bash
xray tls ping example.com:443
```

Target должен стабильно поддерживать TLS 1.3. Собственный домен не требуется.
Для нового местоположения exit-сервера выберите доступный из него стабильный
TLS 1.3 target; страна в конфигурации отдельно не задаётся.

## Повторный запуск

Повторный запуск сохраняет прежние ключи, UUID, клиентскую идентичность и
параметры панели. Конфигурации и правила приводятся к состоянию из шаблонов.

Секреты остаются на серверах:

```text
/root/split-vpn-secrets.json
/etc/x-ui/install-result.env        # только RU
/root/split-vpn-backup/x-ui.db.after-setup
```

Не копируйте эти файлы в Git. Реальные inventory-файлы также добавлены в
`.gitignore`, чтобы случайно не публиковать адреса инфраструктуры.

## Перед публикацией

`.gitignore` исключает реальные inventory-файлы, SSH-ключи, `.env`, локальные
секреты, базы данных, бэкапы и результаты запусков. Не записывайте пароли,
токены и приватные ключи в `group_vars/all.yml`: этот файл является публичной
несекретной конфигурацией. Playbook не скачивает серверные секреты в репозиторий.
